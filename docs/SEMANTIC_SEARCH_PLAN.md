# 類義語検索 実装計画

## 目的

保存済みの原文から、入力した言葉に意味の近い発言を見つけ、その発言がある思考経路へ戻れるようにする。

類義語検索は分類、要約、会話の自動整理を行わない。返すものは、近い順に並んだ保存済み発言の位置である。一致検索は従来どおり先に行い、類義語検索は利用者が明示的に実行する二段目とする。

## 決定

### 検索単位

1つの会話JSONではなく、`Conversation.messages` の1発言を検索単位にする。ユーザーとassistantの両方を対象にし、空本文は索引しない。

各ヒットは次の位置を持つ。

```ts
type SemanticLocation = {
  contentHash: string;
  conversationId: string;
  messageId: string;
  ordinal: number;
  role: MessageRole;
};
```

`contentHash` が原本ファイルを、`messageId` がその中の発言を指す。結果を選ぶと会話全体を開き、該当発言まで移動する。

### 発言と返答の関係

ユーザー発言と後続の返答を、索引上の1件へ結合しない。実際の会話には連続する同一role、`unknown`、補足、脱線があり、一問一答への固定は原文上の位置を曖昧にするためである。

前後関係が必要な画面では、保存された `ordinal` 順からその都度導出する。派生したターンを原本や類義語索引へ保存しない。

### embedding入力

1発言の `content` 全体を1つの入力にする。検索用の要約、言い換え、結合、追加の正規化は行わない。Ollamaへは `truncate: false` を指定し、モデルの文脈長を超えた入力を黙って切り捨てない。

長すぎる発言をOllamaが拒否した場合、その類義語検索は失敗として表示する。部分的な索引を完全な結果として見せない。分割索引は、実データで必要性を確認した後の別変更とする。

### モデル

モデル名はTrailogueの契約として固定しない。机の起動時に明示する。

```bash
npm run desk -- /mnt/f/trailogue --model embeddinggemma
```

モデルの自動取得は行わない。モデルが未指定、未導入、またはOllamaが停止している場合も、机と一致検索は利用できる。類義語検索だけを失敗とする。

### 結果

- コサイン類似度の降順で並べる
- 上位20件を返す
- モデル間で意味が変わる固定スコア閾値は置かない
- 類似度の数値は表示しない
- 一致検索に含まれた発言は類義語検索結果から除く
- 同じ発言を複数回返さない
- 同じ会話の別世代は別の保存記録として扱う
- 同点は `capturedAt`、`conversationId`、`ordinal` で安定させる

近さは結果の並びだけに使い、重要度として扱わない。

## 境界

### 純粋な順位付け

`src/search/rank.ts` を追加する。ここはOllama、ファイル、HTTP、Reactを知らない。

責務:

- ベクトルの検証
- コサイン類似度の計算
- 発言単位の順位付け
- 一致検索ヒットの除外
- 重複除去
- 件数制限と安定した同点順

次元違い、空ベクトル、有限数でない要素は成功として扱わない。入力の `Conversation` とベクトルを変更しない。

### Ollamaクライアント

`src/search/ollama.ts` を追加する。OllamaへのHTTPはこのファイルだけが行う。

責務:

- `http://127.0.0.1:11434/api/embed` へのPOST
- `model`、`input`、`truncate: false` の送信
- 複数発言のバッチ送信
- HTTP状態と応答形式の検証
- 応答件数、ベクトル次元、有限数の検証
- タイムアウト
- 未起動、モデル不明、入力超過、不正応答の失敗化

本文、クエリ、ベクトルを他のoriginへ送らない。Ollamaが失敗したとき、一致検索を類義語検索結果として返すフォールバックは置かない。

### 派生索引

索引は会話JSONへ書かず、保存フォルダ内の派生物として置く。

```text
保存フォルダ/
  {contentHash}.json
  opened-marks
  .trailogue/
    semantic-index-v1.json
```

索引形式:

```ts
type SemanticIndex = {
  version: 1;
  model: string;
  dimensions: number;
  entries: Array<{
    contentHash: string;
    conversationId: string;
    messageId: string;
    ordinal: number;
    role: MessageRole;
    vector: number[];
  }>;
};
```

本文は索引へ複製しない。表示時は必ず検証済みの `Conversation` から原文を読む。

索引は一時ファイルへ書いた後に `rename` する。壊れている、版が違う、モデルが違う、次元が揃わない場合は原本に触れず作り直す。フォルダを正常に読めたときだけ、存在しない `contentHash` の索引を外す。索引から会話JSONを復元しない。

## サーバー処理

既存の `GET /api/search` は一致検索として変更しない。類義語検索用に次を追加する。

```http
POST /api/search/semantic
Content-Type: application/json

{ "query": "探したい言葉" }
```

クエリをURLへ載せない。リクエスト本文には上限を設け、空白だけのクエリを拒否する。

処理順:

1. クエリとモデル設定を検証する
2. 起動時に検証できた `Conversation` だけを対象にする
3. 索引を読み、現在のモデルと原本に対応する有効な行を選ぶ
4. 未索引の発言をOllamaへバッチ送信する
5. 完全に生成できた索引を保存する
6. 同じモデルでクエリのembeddingを生成する
7. `rank.ts` で近い順に並べる
8. 一致検索に含まれる発言を除く
9. 上位20件を発言の位置と原文メタデータ付きで返す

同時に複数の要求が来た場合、同じ索引生成を重複実行しない。索引生成中のPromiseを共有し、検索ごとのクエリembeddingと順位付けだけを分ける。

失敗は少なくとも次を区別する。

| 状態 | 表示 |
| --- | --- |
| モデル未指定 | 起動時にモデルを指定する案内 |
| Ollama未起動・タイムアウト | Ollamaへ接続できない |
| モデル未導入 | 指定したモデルを利用できない |
| 入力超過 | 長すぎる発言があり索引を作れない |
| 不正応答 | Ollamaの応答を利用できない |
| 索引書き込み失敗 | 索引を保存できない |

いずれの場合も一致検索の結果は残す。

## 画面

現在の一致検索は入力に応じて自動実行する。クエリが空なら、これまでどおり玄関を表示する。

一致結果の有無にかかわらず、検索画面に「似た言葉でも探す」を置く。このボタンを押すまでOllamaを呼ばない。

類義語検索の状態:

1. 未実行
2. 索引作成中
3. 検索中
4. 結果あり
5. 結果なし
6. 失敗

結果は一致検索と混ぜず、「似た言葉」の節へ近い順に並べる。各行にはタイトル、role、採取日、発言の原文を表示する。発言を短縮、要約、言い換えしない。類似度は表示しない。

結果を選ぶと会話全体を開き、`messageId` の発言へ移動する。類義語検索では文字列一致を意味しないため、クエリのハイライトは行わない。「結果へ戻る」で、クエリ、一致結果、類義語結果、実行状態を復元する。

クエリを変更した場合、以前の類義語結果はただちに隠す。新しいクエリについては、利用者がもう一度ボタンを押すまで実行しない。

## 実装順

### 1. 純粋関数

- `src/search/rank.ts`
- コサイン類似度
- 入力検証
- 一致結果除外
- 重複除去、上限、同点順
- 単体テスト

この段階ではHTTPと画面を変更しない。

### 2. Ollama境界

- `src/search/ollama.ts`
- 固定originと `/api/embed`
- バッチ入力
- 応答検証と失敗型
- fetchを差し替えた単体テスト

### 3. 索引

- 索引のparse、serialize、検証
- 原本との照合
- 不足分の決定
- 原子的なファイル保存
- モデル変更と破損からの再構築
- 索引生成の排他

### 4. 机API

- 起動引数 `--model`
- `POST /api/search/semantic`
- 一致検索との分離
- エラー応答
- ハンドラーを分離して統合テスト可能にする

### 5. UI

- 明示実行ボタン
- 作成中、検索中、結果、失敗表示
- 発言単位の結果
- 原文位置への移動
- 戻ったときの状態保持
- クエリ変更時の古い結果破棄

### 6. 文書と手動確認

- `README.md` にOllama、モデル導入、起動例を追加
- `docs/ARCHITECTURE.md` に机側の索引境界を追加
- 必要な確定事項を `docs/METHOD.md` に反映
- Ollama停止、モデル未導入、長文、索引破損、再起動後の再利用を手動確認

## テスト計画

### 順位付け

- 意味の近いベクトルが先に来る
- 次元違い、空、`NaN`、`Infinity` を拒否する
- 同じ発言を複数回返さない
- 一致検索で見つかった発言を返さない
- 上位20件に制限する
- 同点順が安定する
- 入力と保存本文を変更しない

### Ollama

- `127.0.0.1:11434` 以外へ送らない
- `/api/embed` に `truncate: false` を送る
- 文字列配列の順と応答ベクトルの順が対応する
- 応答件数と次元を検証する
- タイムアウト、接続失敗、404、不正JSONを失敗にする
- 失敗時に一致検索結果を類義語結果として返さない

### 索引

- 同じモデルと `contentHash` の索引を再利用する
- 新しい発言だけを追加する
- モデル変更時に再構築する
- 破損ファイルから原本を変更せず再構築する
- 原本が確認できないとき索引を消さない
- 原本が確認できたとき不要な索引を外す
- 一時ファイルから原子的に置き換える
- 索引に本文を保存しない

### UI

- 入力だけではOllamaを呼ばない
- 一致結果が0件でも類義語検索を実行できる
- 一致結果を残したまま類義語結果を表示する
- 類義語結果に一致検索の発言を重ねない
- 生成中、検索中、失敗を区別する
- ヒットから該当発言へ移動する
- 類義語結果では文字列をハイライトしない
- 結果へ戻ると以前の状態が残る
- クエリ変更後に古い類義語結果を表示しない

## 完了条件

- 保存済み発言を1発言単位で類義語検索できる
- ヒットから原文の該当発言へ戻れる
- 会話JSONと本文が一切変わらない
- 本文とクエリをOllama以外へ送らない
- Ollamaが使えなくても机と一致検索は動く
- 類義語検索の失敗を一致検索で偽装しない
- 索引を削除しても検証済みJSONから作り直せる
- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build` が通る
